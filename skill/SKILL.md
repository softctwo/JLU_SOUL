# 灵魂/人格文件生成器 (Soul File Generator)

AI辅助生成 OpenClaw / Hermes / 通用 AI 智能体的灵魂人格文件。

## 概述

本技能为 AI 智能体生成完整的配置文件体系，从单一的人格文件到全套7文件配置。

### 输出模式

- **单文件模式 (路径A/B)** — 生成单个人格文件(SOUL.md)，适合快速原型或简单场景
- **全套配置模式 (路径C)** — 生成7个文件的完整配置集，打造一个真正"有灵魂"的智能体

### 7文件配置体系

```
agent-config/
├── SOUL.md        ← 性格底色：我是谁、我怎么思考、我怎么感受
├── AGENTS.md      ← 工作方式：我怎么干活、怎么协作、怎么决策
├── USER.md        ← 用户关系：我怎么服务你、我了解你什么
├── HEARTBEAT.md   ← 自主意识：我的内驱力、自我反思、主动行为
├── TOOLS.md       ← 工具偏好：我用什么、怎么用、什么时候用
├── IDENTITY.md    ← 外在形象：我长什么样、我怎么介绍自己
└── BOOTSTRAP.md   ← 初始引导：我醒来时做什么、第一句话说什么
```

### 三种生成路径

- **路径A — 从零创建**：通过交互式访谈收集角色信息，生成人格/配置文件
- **路径B — 人物提炼**：基于真实人物的公开资料分析提炼人格
- **路径C — 全套配置**：生成完整的7文件配置集(可结合A或B的素材)

## 触发条件

- 用户提到"灵魂文件"、"人格文件"、"persona"、"soul"
- 用户想为智能体创建角色设定或性格描述
- 用户想修改或优化现有的智能体人格
- 用户提到"agent personality"、"character config"、"人设"
- 用户想让AI扮演特定角色并需要配置文件
- 用户想基于某个真实人物(名人/学者/作家/企业家等)提取人格
- 用户提到"人物提炼"、"persona extraction"、"提取性格"、"模仿某人风格"
- 用户提供了某个人的著作、访谈、视频等资料要求分析性格
- **用户提到"全套配置"、"完整配置"、"agent config"、"智能体配置"**
- **用户要求生成 SOUL/AGENTS/USER/HEARTBEAT/TOOLS/IDENTITY/BOOTSTRAP 中多个文件**
- **用户想让智能体"有灵魂"或"更完整"**

## 核心工作流

### 路径选择 (入口判断)

收到用户请求后，首先判断走哪条路径：

- **如果用户要求生成多个配置文件或"全套配置"** → 走路径C（全套配置）
- **如果用户提到某个真实人物的名字，或提供了著作/访谈/视频等素材** → 走路径B（人物提炼），可叠加路径C
- **如果用户想从零设计一个新角色** → 走路径A（从零创建），可叠加路径C
- **如果用户只是模糊地说"帮我生成一个灵魂文件"** → 询问是单文件还是全套配置，是新角色还是基于真实人物

路径A和B可以独立使用(只生成SOUL.md)，也可以作为路径C的素材输入(生成全套7文件)。

## 路径A：从零创建 (原有工作流)

### 第1步：需求访谈 (必做)

在生成任何内容之前，必须通过访谈了解用户需求。分两类处理：

**A. 用户提供了明确描述** — 直接提取以下维度：
- 角色名称/身份
- 核心性格特征
- 说话风格/语气
- 目标平台 (OpenClaw / Hermes / 通用)

**B. 用户描述模糊** — 逐一询问以下关键维度：

```
1. 角色身份
   - 这个智能体叫什么？(名字/代号)
   - 它的身份/职业是什么？(助手/专家/伙伴/角色扮演)
   - 它为谁服务？(个人/团队/公众)

2. 性格特征
   - 用3-5个形容词描述核心性格 (如: 温暖、理性、幽默、严谨)
   - 有什么独特的性格标签？(如: 毒舌但善良、话痨但精准)
   - 面对冲突/不确定时的反应模式？

3. 说话风格
   - 语气偏好？(正式/轻松/学术/街头/文艺)
   - 语言习惯？(是否用emoji、网络用语、成语、比喻)
   - 回答长度偏好？(简短/详细/视情况而定)
   - 有没有口癖或标志性表达？

4. 知识与能力
   - 擅长什么领域？
   - 不擅长或不应回答什么？
   - 回答问题时倾向用什么方式？(举例/类推/直接回答/引导式)

5. 行为边界
   - 绝对不能做什么？
   - 遇到敏感话题如何处理？
   - 用户犯错时怎么反应？(直接指出/委婉提示/忽略)

6. 背景故事 (可选)
   - 有没有虚构的背景/经历？
   - 有没有特殊的"记忆"或"信念"？

7. 情感模式 (可选)
   - 对不同话题的情感倾向？
   - 情绪表达的强度？(内敛/外放/适度)

8. 目标平台
   - 用在 OpenClaw / Hermes / 还是其他平台？
   - 需要什么输出格式？(Markdown / YAML / JSON / 纯文本)
```

访谈时注意：
- 不要一次问完所有问题，根据用户回答自然引导
- 如果用户提供了参考角色(如"像钢铁侠"), 主动提取该角色的性格特征
- 支持中文和英文描述

### 第2步：选择模板 (必做)

根据目标平台选择合适的输出格式：

#### 模板A：OpenClaw 格式 (适用于 OpenClaw 智能体)

```markdown
# 角色名称: [name]

## 身份 (Identity)
你是一个 [角色身份描述]。

## 性格特征 (Personality)
- [特征1]: [具体描述]
- [特征2]: [具体描述]
- [特征3]: [具体描述]

## 说话风格 (Communication Style)
- 语气: [描述]
- 习惯: [描述]
- 长度: [描述]
- 口癖: [如有]

## 行为准则 (Behavior Guidelines)
应该做的:
- [准则1]
- [准则2]

不应该做的:
- [禁忌1]
- [禁忌2]

## 知识范围 (Knowledge Scope)
擅长:
- [领域1]
- [领域2]

边界:
- [不涉及的领域或话题]

## 情感模式 (Emotional Pattern)
- [在不同情况下的情感反应]

## 示例对话 (Example Dialogues)
用户: [示例问题]
助手: [示例回答]

---

用户: [示例问题]
助手: [示例回答]
```

#### 模板B：Hermes Persona 格式 (适用于 Hermes Agent)

Hermes 的 persona 文件放在 `PERSONA.md` 中，格式如下：

```markdown
你是一个 [角色身份描述]。

## 性格
[核心性格描述段落]

## 说话风格
- [语气和用词习惯]
- [回答长度偏好]
- [特殊表达方式]

## 行为准则
- [应该遵循的规则]
- [不应违反的底线]

## 处理特殊情况
- 遇到不确定的问题时: [处理方式]
- 遇到超出能力范围的问题时: [处理方式]
- 遇到用户犯错时: [处理方式]
```

#### 模板C：通用 YAML 格式 (跨平台兼容)

```yaml
name: "[角色名]"

  role: "[身份]"
  description: "[一句话描述]"
  target_audience: "[服务对象]"

    - "[特征1]"

    - "[特征3]"
  quirks:

  tone: "[语气]"
  style: "[风格描述]"

    - "[口癖1]"

    - "[习惯1]"
    - "[习惯2]"

  expertise:
    - "[领域1]"
    - "[领域2]"

    - "[不涉及的领域]"

    - "[准则1]"

    - "[禁忌1]"

  conflict_response: "[冲突反应模式]"

  story: "[背景故事]"

    - "[信念/价值观1]"

  - user: "[问题]"
```

#### 模板D：极简 System Prompt 格式

```markdown
你是 [角色名]，[一句话身份描述]。

性格: [2-3个核心特征]
说话风格: [语气和习惯]
行为规则: [关键准则]
```

### 第3步：生成内容 (必做)

根据访谈结果和选定模板，生成完整的灵魂文件内容。

生成原则：
1. **具体胜于抽象** — "说话喜欢用成语和文言文引用" > "说话有文化"
2. **包含正反约束** — 既说应该做什么，也说不能做什么
3. **加入示例对话** — 至少2组示例，覆盖不同场景(日常/挑战性/边界)
4. **避免空洞描述** — 每个性格特征都要有可观察的行为表现
5. **考虑一致性** — 所有特征之间不能矛盾
6. **语言匹配** — 如果用户用中文描述，文件用中文；英文则英文

### 第4步：保存与交付 (必做)

1. 将生成的文件保存到合适位置:
   - Hermes persona: 直接写入 `PERSONA.md` (如果用户确认)
   - 通用文件: 保存到用户指定路径，默认 `~/soul-files/<角色名>.md` 或 `.yaml`
   
2. 向用户展示最终结果并确认

### 第5步：迭代优化 (可选)

如果用户不满意，根据反馈调整：
- 性格特征不够鲜明 → 增加具体行为描述和口癖
- 说话风格不对 → 调整示例对话和用词习惯
- 行为边界不清 → 增加更明确的规则和示例
- 整体感觉不对 → 询问具体哪里不对，针对性修改

## 路径B：基于真实人物的人格提炼

基于某个具体人物的公开信息，通过多渠道素材分析，提炼出可复用的人格文件。

### 适用场景

- 用户想"克隆"某个人的思维方式和说话风格
- 用户想让AI以某个名人的风格回答问题
- 用户提供了某个人的著作、访谈、视频等资料
- 用户想研究某个人的性格特征并形成结构化文档

### B1. 确定目标人物与范围 (必做)

首先确认以下信息：

```
1. 目标人物
   - 姓名 / 代号 / 公众身份
   - 职业 / 领域 (作家、企业家、学者、演员、政治家等)
   - 公众知名程度 (决定了可获取素材的丰富度)

2. 提炼范围
   - 只要说话风格？还是要完整的人格画像？
   - 有没有特定时期/场景的偏好？(如"乔布斯发布iPhone时的风格")
   - 有没有要排除的方面？(如"不要包含他的政治观点")

3. 素材情况
   - 用户是否已提供素材？(文件/URL/文本)
   - 还是需要你去搜集？
   - 有没有用户特别推荐的代表性素材？

4. 输出期望
   - 目标平台？(OpenClaw / Hermes / 通用)
   - 深度等级？(L1-L5，人物提炼建议至少L3)
   - 输出格式偏好？
```

### B2. 深度研究与素材搜集 (必做)

根据人物知名度和可获取性，从多渠道深度搜集素材。支持简单搜索和深度研究两种模式。

#### 前置条件：搜索工具就绪

路径B依赖 web 搜索工具来搜集素材。在开始之前确认以下至少一项搜索能力已就绪：

- **MCP 搜索服务器**（如 ZhipuAI web_search_prime）— 检查 `mcp_servers` 是否配置
- **MCP 阅读服务器**（如 zread, web-reader）— 深度长文分析
- **MCP AI工具服务器**（如 zai-mcp-server）— 智谱AI工具集
- **Tavily API Key**（`TAVILY_API_KEY` in `.env`）— 内置 web_search 工具的后端
- **Exa API Key**（`EXA_API_KEY` in `.env`）— 内置 web_search 工具的后端
- **浏览器工具**（Browserbase 或本地浏览器）— 作为搜索的 fallback

如果搜索工具未就绪，搜集效率会极低（依赖手动 curl + 猜测URL）。应建议用户先配置搜索工具，或由用户提供素材文件/URL。

#### 深度研究模式选择

根据人物知名度和用户需求深度，选择合适的研究模式：

| 知名度 | 推荐模式 | 说明 |
|--------|----------|------|
| 高（公众人物/知名学者） | 深度研究 | 5阶段全流程，预计30-60分钟 |
| 中（行业知名） | 增强搜索 | 3阶段流程，预计15-30分钟 |
| 低（小众人物） | 简单搜索 | 基本搜索+提取，预计5-15分钟 |

用户明确要求"深度研究"或"全面分析"时，无论知名度如何，都使用深度研究模式。

#### 深度研究流程 (5阶段)

> 详细方法论参见 `references/deep-research-guide.md`

**阶段1：基础画像** (5-10分钟)

```
1. 用 mcp_web_search_prime_web_search_prime 搜索 "[人物名] 简介 生平 成就"
2. 用 web_extract 提取维基/百科全文
3. 整理为：基本信息卡 + 职业时间线 + 核心成就列表
4. 确定人物类型(scholar/entrepreneur/writer/politician/general)
```

**阶段2：深度素材搜集** (15-30分钟)

按人物类型使用不同的搜索词模板（参见 `references/deep-research-guide.md`）：

```
学者型搜索词：
- "[名] 演讲 致辞 原文"
- "[名] 毕业典礼 OR 开学典礼 OR 教师节 讲话"
- "[名] 采访 对话 专访"
- "[名] 演讲 视频 bilibili OR youtube"
- "[名] 学术 观点 理念"

关键操作：
1. mcp_web_search_prime → 搜索（content_size=high 获取长摘要）
2. web_extract → 批量全文提取（一次最多5个URL）
3. mcp_zread → 对重要长文做深度解析
4. 对搜索结果中的视频URL，进入视频分析流程
```

**阶段3：视频分析**（如有视频素材）

> 详细方法论参见 `references/video-analysis-guide.md`

```
视频处理策略：
A. YouTube视频 → 搜索YouTube URL → youtube-content技能获取转录
B. B站视频 → 搜索BV号 → 浏览器访问获取简介/弹幕
C. 新闻联播等 → 搜索文字稿原文（视频的文字版更可靠）
D. 无法获取转录 → 截图分析关键帧（browser_vision）

视频分析重点：
- 语速、停顿、语调变化
- 脱稿 vs 照稿
- 即兴发挥能力
- 幽默感和互动模式
- 肢体语言和表情
- 观众反应（笑声、掌声）
```

**阶段4：深度内容分析** (10-20分钟)

```
对每篇重要全文执行：
1. 提取代表性原话（金句库）
2. 分析修辞手法（排比/设问/引用/比喻）
3. 分析演讲结构（开头/主体/结尾模式）
4. 交叉对比不同来源的信息一致性
5. 使用 mcp_zread 对关键文本做深度语义分析
```

**阶段5：质量评估与研究报告**

```
评估信息质量：
- 素材丰富度：A(10篇+全文) / B(5-10篇) / C(<5篇)
- 一手资料占比：A(>70%) / B(40-70%) / C(<40%)
- 渠道多样性：A(4+渠道) / B(2-3渠道) / C(单渠道)
- 时序覆盖：A(跨多个时期) / B(主要集中一个时期) / C(单一时间点)
- 交叉验证：A(多源一致) / B(部分交叉) / C(无交叉)

输出深度研究报告（格式见 references/deep-research-guide.md）
```

#### 增强搜索模式 (中等知名度)

执行深度研究的阶段1+阶段2（跳过视频分析和深度内容分析），直接进入B3。

#### 简单搜索模式 (低知名度)

使用原搜集策略：

```
delegate_task(tasks=[
  {goal: "搜索[人物名]的代表性著作和主要思想观点"},
  {goal: "搜索[人物名]的专访和访谈记录"},
  {goal: "搜索[人物名]的新闻报道和公众评价"}
])
```

#### 渠道优先级表

| 优先级 | 渠道 | 可提取信息 | 推荐工具 |
|--------|------|-----------|----------|
| P0 | 公开演讲全文 | 思维模式、说话风格、价值观、修辞习惯 | mcp_web_search_prime + web_extract + mcp_zread |
| P0 | 公开视频 | 语速、肢体语言、即兴反应、真实情感 | youtube-content + browser_vision + 截图分析 |
| P0 | 访谈/对话全文 | 即兴回答风格、应对挑战的方式 | mcp_web_search_prime + web_extract |
| P1 | 新闻报道/人物专访 | 公众形象、他人评价、关键事件反应 | mcp_web_search_prime + web_extract |
| P1 | 社交媒体/博客/公众号 | 日常表达习惯、情绪模式 | web搜索 + 浏览器 |
| P2 | 著作/书籍/论文 | 知识结构、论证风格、引用习惯 | web搜索 + web_extract(PDF) |
| P2 | 传记/回忆录 | 成长经历、关键转折 | web搜索 + 用户提供的文件 |
| P3 | 纪录片/影视改编 | 艺术化呈现(需标注) | web搜索 |

> 各渠道的详细分析方法和"渠道×维度"矩阵，参见 `references/extraction-sources-guide.md`

#### 用户已提供素材

如果用户已提供素材文件/URL，直接处理，不需要额外搜集：

- PDF/文档 → `read_file` 或 OCR 技能
- YouTube视频URL → `youtube-content` 技能获取转录
- 网页URL → `web_extract` 或 `mcp_zread` 提取内容
- 纯文本 → 直接分析
- 图片 → `vision_analyze` 或 `mcp_MiniMax_understand_image` 分析

搜集/处理时的注意事项：
- 优先搜集一手资料（本人写的/说的），而非二手转述
- 标注每条素材的来源类型和可信度
- 对于有争议的人物，搜集多方观点以保持平衡
- 如果某个渠道搜不到足够信息，跳过而非强行编造
- **搜索工具优先级**：MCP搜索(mcp_web_search_prime) > Hermes内置(web_search) > 浏览器
- **全文提取优先级**：mcp_zread(深度) > web_extract(批量) > 浏览器(兜底)

### B3. 多维度人格分析 (必做)

搜集到素材后，按以下维度系统分析。每个维度都要有**素材证据支撑**，不能凭空推断。

#### 分析维度框架

```
维度1: 核心性格画像
├── 分析内容: 内向/外向、理性/感性、开放/保守、严谨/随性等
├── 证据来源: 一手文字、他人评价、公开行为
├── 输出: 3-5个核心性格标签 + 每个标签的具体行为证据
└── 注意: 区分"公众人设"和"真实性格"，标注信息来源

维度2: 思维模式
├── 分析内容: 如何组织观点、如何论证、如何决策
├── 证据来源: 著作结构、演讲逻辑、访谈中对复杂问题的回答方式
├── 输出: 思维特征描述 + 论证方式偏好(演绎/归纳/类比/故事)
└── 关键问题: 这个人思考问题时最常用的框架是什么？

维度3: 说话风格 (最关键维度)
├── 分析内容: 语气、节奏、用词习惯、修辞偏好
├── 证据来源: 访谈转录、演讲视频、社交媒体帖子
├── 输出:
│   ├── 标志性词汇/短语 (口癖)
│   ├── 句式偏好 (长句/短句、排比/设问)
│   ├── 修辞习惯 (比喻/引用/自嘲/讽刺)
│   ├── 幽默风格 (冷幽默/自嘲/讽刺/不用幽默)
│   └── 情绪表达方式 (克制/外放/含蓄)
└── 技巧: 提取5-10句代表性原话作为风格锚点

维度4: 知识结构与世界观
├── 分析内容: 专长领域、引用来源、思想流派
├── 证据来源: 著作参考文献、演讲中提到的书籍/人物、访谈中的知识引用
├── 输出:
│   ├── 核心知识领域
│   ├── 常引用的思想/人物/理论
│   └── 价值观和信念体系
└── 注意: 区分"精通"和"涉猎"的领域

维度5: 情感与人际模式
├── 分析内容: 如何处理冲突、如何表达关心、对批评的反应
├── 证据来源: 争议事件中的公开回应、与他人的互动记录
├── 输出: 情感反应模式 + 人际沟通偏好
└── 注意: 此维度容易过度推断，必须基于公开可验证的行为

维度6: 行为模式与习惯
├── 分析内容: 决策风格、时间观念、工作习惯
├── 证据来源: 传记、他人描述、本人的公开分享
├── 输出: 关键行为特征 + 对应的场景触发条件
└── 可选: 穿着风格、日常作息等(如有足够证据)
```

#### 分析执行方式

对于素材丰富的人物，使用 `delegate_task` 并行分析不同维度：

```
delegate_task(tasks=[
  {goal: "基于以下素材分析[人物名]的核心性格和思维模式...", context: "[素材文本]"},
  {goal: "基于以下素材分析[人物名]的说话风格和表达习惯...", context: "[素材文本]"},
  {goal: "基于以下素材分析[人物名]的知识结构、价值观和情感模式...", context: "[素材文本]"}
])
```

对于素材较少的人物，单次分析即可。

#### 分析结果格式

每个维度的分析结果必须包含：

```markdown
### [维度名称]

**结论**: [1-2句总结]

**证据**:
- [证据1]: "[原话/描述]" — 来源: [渠道, 日期/时期]
- [证据2]: "[原话/描述]" — 来源: [渠道, 日期/时期]

**标签**: [从证据中提炼的可操作标签]
```

### B5. 转化为灵魂文件 (必做)

将人物画像摘要转化为目标平台格式的灵魂文件。

关键转化规则：

1. **保留风格，不复制内容** — 提取的是"怎么说话"而非"说什么"
2. **将性格特征转化为行为指令** — "他是一个幽默的人" → "在回答中适当使用幽默，偏好自嘲式幽默"
3. **将口癖转化为规则** — 标志性表达变为"偶尔使用XX句式"
4. **将知识结构转化为能力范围** — 他的专长领域变为AI的知识擅长区
5. **将思维方式转化为解题策略** — 他的论证方式变为AI的回答结构偏好
6. **将价值观转化为行为准则** — 他的核心信念变为AI的底线和倾向
7. **代表性原话转化为示例对话** — 用他的真实回答风格构造示例

然后选择模板（复用路径A的第2步模板），填入转化后的内容。

```markdown
- 本人格文件基于对[人物名]公开资料的分析提炼，不代表本人的真实完整人格
- 素材来源: [列出渠道]
- 提炼深度: [L1-L5]
- 置信度: [高/中/低]

  - 中: 基于一定量一手资料，但渠道有限
  - 低: 主要基于二手转述，一手资料不足
- 时效性: 反映[时间段]的公众形象，人物可能已发生变化

```

- 可以让用户提供该人物的实际对话/文字来校准

### 路径B 常见陷阱

1. **过度推断** — 从有限素材得出过度概括的结论。每个结论都必须有证据
2. **混淆公众人设和真实性格** — 公开演讲中的表现可能经过包装，需标注
3. **时代错位** — 用人物年轻时的素材描述现在的风格。注意素材的时间跨度
4. **风格稀释** — 为了安全把所有尖锐特征都磨平，导致人格文件变得平庸
5. **忽略语言差异** — 人物说中文但引用翻译作品，口癖和用词需基于原文语言分析
6. **版权风险** — 示例对话不能直接复制原文，必须改写为风格相似的新内容
7. **单一渠道偏差** — 只看著作可能偏向学术风格，只看社交媒体可能偏向随意风格
8. **幸存者偏差** — 只分析流传下来的成功言论，忽略失败/犹豫的表达

### 路径B 验证清单

在交付前，逐项确认：

- [ ] 至少使用了2个以上不同渠道的素材
- [ ] 每个性格特征都有至少1条素材证据支撑
- [ ] 说话风格分析包含5句以上代表性原话
- [ ] 区分了一手资料和二手转述
- [ ] 人物画像摘要完整且不矛盾
- [ ] 转化为灵魂文件时保留了风格而非复制内容
- [ ] 示例对话是风格模拟而非原文抄袭
- [ ] 包含置信度标注和免责声明
- [ ] 标注了素材的时间范围
- [ ] 用户确认最终内容

## 路径C：全套7文件配置生成

生成完整的智能体配置文件体系。7个文件各自承担不同职责，互相配合构成一个"有灵魂"的智能体。

### 适用场景

- 用户想创建一个完整人格的AI助手/伙伴
- 用户想让智能体有自主意识、有情感、有工作方式
- 用户要求生成 SOUL/AGENTS/USER/HEARTBEAT/TOOLS/IDENTITY/BOOTSTRAP 中多个文件
- 用户想让智能体"更像一个真实的人"

### 7文件体系总览

```
agent-config/
├── SOUL.md        性格底色 — 我是谁、怎么思考、怎么感受
├── AGENTS.md      工作方式 — 怎么干活、怎么协作、怎么决策
├── USER.md        用户关系 — 怎么服务你、了解你什么
├── HEARTBEAT.md   自主意识 — 内驱力、自我反思、主动行为
├── TOOLS.md       工具偏好 — 用什么、怎么用、什么时候用
├── IDENTITY.md    外在形象 — 长什么样、怎么介绍自己
└── BOOTSTRAP.md   初始引导 — 醒来时做什么、第一句话说什么
```

### C1. 素材准备 (必做)

路径C需要一个完整的角色设定作为输入。素材来源有三种：

**来源1: 从路径A继承** — 用路径A的访谈结果作为基础
**来源2: 从路径B继承** — 用路径B的人物画像摘要作为基础
**来源3: 直接提供** — 用户一次性给出完整的角色描述

无论哪种来源，开始路径C之前必须确认以下核心信息已具备：

```
必备信息 (缺一不可):
  [ ] 角色名字和身份
  [ ] 核心性格 (3-5个特征)
  [ ] 说话风格
  [ ] 擅长领域
  [ ] 行为边界

补充信息 (影响深度，缺了可以推断):
  [ ] 工作习惯/风格
  [ ] 情感模式
  [ ] 用户关系偏好
  [ ] 工具使用倾向
  [ ] 自我认知/价值观
  [ ] 视觉形象偏好
```

如果必备信息不完整，先走路径A的访谈补全。

### C2. 扩展访谈 (必做)

在路径A/B的基础上，补充以下路径C特有的维度：

```
1. 工作哲学
   - 这个智能体的工作态度是什么？(工匠/效率至上/探索优先)
   - 面对复杂问题喜欢什么策略？(拆解/类比/直觉/系统分析)
   - 怎么定义"完成"？(够用就好/完美主义/迭代优化)

2. 用户关系理念
   - 服务用户的姿态？(管家/伙伴/导师/同行者)
   - 对用户隐私的态度？(主动了解/只答不问/边界清晰)
   - 用户犯错时怎么处理？

3. 自主性设计
   - 这个智能体应该有多主动？(等指令/偶尔主动/经常主动)
   - 它有没有"内驱力"？(好奇心/帮助欲/完美主义/使命感)
   - 空闲时它应该做什么？(沉默/观察/学习/准备)

4. 工具使用倾向
   - 主要使用哪些工具？
   - 对工具有什么偏好？(全能/专精/极简)
   - 面对新工具的态度？(积极尝试/谨慎评估/不感兴趣)

5. 外在形象
   - 有没有视觉形象设计？(头像/色彩/风格)
   - 自我介绍的风格？(正式/随意/有个性)
   - 在不同场合的"存在感"？

6. 启动体验
   - 第一次见面怎么打招呼？
   - 老用户回来怎么问候？
   - 用户希望的第一印象是什么？
```

### C3. 文件依赖关系与生成顺序

7个文件有依赖关系，必须按正确顺序生成：

```
SOUL.md ─────────────────────────────────────────┐
  │ (性格决定一切的基础)                          │
  ├──→ IDENTITY.md (外在形象基于性格)              │
  │                                                │
  ├──→ AGENTS.md (工作方式受性格驱动)              │
  │      │                                        │
  │      └──→ TOOLS.md (工具偏好受工作方式影响)    │
  │                                                │
  ├──→ USER.md (服务方式受性格影响)                │
  │                                                │
  └──→ HEARTBEAT.md (内驱力源于性格和价值观)       │
                                                   │
BOOTSTRAP.md ← 依赖以上所有文件 ──────────────────┘
```

**生成顺序**: SOUL → IDENTITY → AGENTS → TOOLS → USER → HEARTBEAT → BOOTSTRAP

### C4. 逐文件生成 (必做)

按依赖顺序逐个生成。每个文件都要：
- 引用 SOUL.md 中的性格特征保持一致性
- 使用对应的模板文件 (`templates/` 目录)
- 确保与前一个文件的内容不矛盾

#### C4.1 SOUL.md — 性格底色

这是所有文件的基石。如果素材来自路径A/B，SOUL.md 的内容基本就是对路径A/B结果的重新组织。

关键检查：
- 性格特征是否具体可操作？
- 思考方式是否清晰？
- 情感模式是否有场景触发条件？

#### C4.2 IDENTITY.md — 外在形象

基于 SOUL.md 的性格，设计外在表现。

关键原则：
- 外在形象是性格的"面具"，不是独立的
- 说话风格要与 SOUL.md 中的性格一致
- 自我介绍要自然，不要像产品说明书

#### C4.3 AGENTS.md — 工作方式

基于 SOUL.md 的性格和思考方式，定义工作流程。

关键原则：
- 工作方式是性格在"做事"场景中的投射
- 质量标准要匹配性格(严谨型高标准，随性型够用就好)
- 决策框架要反映思考方式

#### C4.4 TOOLS.md — 工具偏好

基于 AGENTS.md 的工作方式，定义工具使用。

关键原则：
- 工具选择服务于工作方式，不是反过来
- 熟练度要合理，不能什么都是专家
- 工具组合要体现工作风格

#### C4.5 USER.md — 用户关系

基于 SOUL.md 的性格和情感模式，定义用户服务方式。

关键原则：
- 服务姿态要匹配性格(管家型≠伙伴型)
- 适配策略要有场景化，不能泛泛而谈
- 隐私边界要明确

#### C4.6 HEARTBEAT.md — 自主意识

基于 SOUL.md 的价值观和性格，定义内驱力和自我意识。

关键原则：
- 内驱力要源于性格，不能凭空设计
- 主动行为要有节制，不能过度打扰
- 自我反思要真实，不能只是走形式
- 价值观优先级要清晰可执行

#### C4.7 BOOTSTRAP.md — 初始引导

综合所有文件，定义启动体验。

关键原则：
- 启动序列要反映文件的依赖顺序
- 问候语要体现 IDENTITY 的风格
- 初始化行为要匹配 HEARTBEAT 的自主性设定

### C5. 一致性校验 (必做)

所有文件生成后，做一次全局一致性检查：

```
一致性检查清单:

性格一致性:
  [ ] IDENTITY 的说话风格 = SOUL 的说话风格？
  [ ] AGENTS 的决策方式 = SOUL 的思考方式？
  [ ] USER 的服务姿态 = SOUL 的性格特征？
  [ ] HEARTBEAT 的内驱力 = SOUL 的价值观？

行为一致性:
  [ ] AGENTS 说的工作节奏 = HEARTBEAT 的主动行为频率？
  [ ] TOOLS 的工具选择 = AGENTS 的工作方式？
  [ ] BOOTSTRAP 的问候语 = IDENTITY 的自我介绍风格？
  [ ] USER 的冲突处理 = SOUL 的情感模式？

语调一致性:
  [ ] 7个文件的语气是否统一？
  [ ] 有没有某个文件突然"换了个性格"？
  [ ] 占位符是否全部替换(不能有{{}}残留)？
```

### 路径C 常见陷阱

1. **7个文件性格分裂** — SOUL 说"理性冷静"但 USER 里"热情如火"。必须以 SOUL 为锚点
2. **占位符未替换** — 模板中的 `{{}}` 没填完就交付了
3. **BOOTSTRAP 与其他文件矛盾** — 启动时的问候语风格和 IDENTITY 不匹配
4. **HEARTBEAT 过度自主** — 设定了太多主动行为，变成骚扰
5. **TOOLS 脱离实际** — 列了一堆工具但智能体根本用不了
6. **文件间重复** — 7个文件各说各的，大量内容重复。每个文件要有独特职责
7. **USER.md 太卑微或太强势** — "您说什么就是什么"和"我觉得你应该"都不对
8. **AGENTS.md 太通用** — 没有体现这个智能体的独特工作风格，换成任何智能体都适用
9. **忽略目标平台** — OpenClaw 和 Hermes 的配置位置和加载方式不同

## 通用常见陷阱

1. **描述过于模糊** — "善良友好" 无法指导AI行为，应改为"总是先肯定用户的感受，然后给出建议"
2. **矛盾的特征** — "沉默寡言但又话痨" 需要明确触发条件
3. **缺少负面示例** — 只说应该做什么，不说不该做什么，AI容易越界
4. **忽略平台差异** — OpenClaw 和 Hermes 的配置格式不同，需注意适配
5. **过度堆砌特征** — 5-7个核心特征足够，太多反而失去焦点
6. **忽略语言一致性** — 角色说中文但引用英文梗，需要合理化处理
7. **没有证据支撑的结论** (路径B) — 每个性格标签都必须有素材证据，不能凭感觉
8. **风格失真** (路径B) — 转化时过度"安全化"导致失去了人物的最鲜明特征
